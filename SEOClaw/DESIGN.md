# SEOClaw 设计系统

> 这份文件是唯一事实来源。CSS、组件都是它的投影。两者若冲突，以本文为准。

## Phase 0 — 定调（先定词，再动像素）

**这是什么**：工具型 SaaS 应用（审计报告），不是营销页。
用户是站长 / 增长负责人 / 接手别人站的开发。他们要的是**一份可以照着改的清单**，
不是一个漂亮的落地页。所以密度优先、结论前置、证据可展开。

**给谁**：手上有活要干的技术决策者。他们自己看代码、自己在后台改，
不需要被说服，只需要被指路。

**一次要完成的事**：填一个网址 → 拿到一份「先改哪几件」的清单。

**3–5 个品牌词**：严谨 · 可核查 · 克制 · 有分量 · 不谄媚

**审美三词**：**仪器 · 公文 · 墨线**

## Phase 1 — 系统

### 1. 审美方向

**审计报告的物质感**。参照物不是 SaaS 仪表盘，是**检验报告 / 计量器具**：
纸白底、墨黑字、等宽字号的规则编号、刻度线、盖章式的印章红点缀。

刻意放弃：蓝紫渐变、发光阴影、圆角气泡、居中 hero + 三张卡片。

### 2. 字体

**IBM Plex 家族**（Sans + Mono + Sans SC），单一家族三层。

- 为什么是它：工程与审计气质，天生的字腔方、字距稳；中文（IBM Plex Sans SC）
  与西文等高不错位；等宽字用于规则编号和 URL，是**功能需求**不是装饰。
- 明确不用：Inter / Roboto / Arial / system-ui 作主字——那是 AI 味的默认中位数。
- 本机可能拉不到 CDN 字体，因此**回退栈必须完整可用**，不是摆设。

| 角色 | 字体 | 字号 / 字重 / 行高 |
|---|---|---|
| 数字与总分 | Plex Mono | 56 / 500 / 1 |
| 标题 h1 | Plex Sans 600 | 32 / 600 / 1.2 |
| 正文 | Plex Sans 400 | 14.5 / 400 / 1.65 |
| 标签与刻度 | Plex Mono 500 | 11 / 500 / 1.4，字距 .06em，大写 |
| 代码 | Plex Mono 400 | 12.5 / 400 / 1.7 |

字号阶梯：比例 1.2，基准 14.5 → 11.5 / 14.5 / 17.4 / 20.9 / 25.1 / 30.1

### 3. 颜色（OKLCH）

蓝紫是 AI UI 的红海，整体绕开。只留一个强调色，且用得很省。

| 角色 | OKLCH | 用途 |
|---|---|---|
| `--bg` | `oklch(0.985 0.002 90)` | 纸白，暖调 |
| `--surface` | `oklch(1 0 0)` | 卡片 |
| `--fg` | `oklch(0.21 0.01 90)` | 墨黑 |
| `--fg-2` | `oklch(0.42 0.01 90)` | 次级 |
| `--muted` | `oklch(0.58 0.008 90)` | 说明文字 |
| `--line` | `oklch(0.91 0.004 90)` | 分隔线 |
| `--accent` | `oklch(0.52 0.115 62)` | **琥珀**：刻度、进度、选中 |
| `--stamp` | `oklch(0.48 0.16 25)` | **印章红**：仅严重级徽标 |

语义：`--ok` / `--warn` / `--err` 低饱和，绝不用颜色单独表意（旁边永远有文字）。

**比例 60-30-10**：纸白与墨黑占 85%，琥珀 < 10%，印章红 < 2%。

### 4. Token 表

- 间距基数 **4px**：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。组内紧，组间松。
- 圆角**只有两个**：`2px`（徽标、进度条）与 `4px`（卡片）。不给胶囊。
- 阴影：**全系统不用阴影**。层级只靠 1px 边框和留白。这是「仪器」观感的来源。

### 5. Signature move

**带刻度的量规**。健康分不是一根进度条，是一把**尺**：0–100 上刻 11 道，
每 10 分一道长线、每 2 分一道短线，得分位置立一根墨黑标记。
另外每个问题条目带**等宽体规则编号** `R-001`，像审计报告的条目号。

### 6. 适配方式

纯 CSS 自定义属性（无框架），token 直接写在 `:root`。

## Phase 2 — 工艺层决策

**布局**：单列 940px，**不使用**「居中最大宽列」的肌肉记忆——表单区用
`grid-template-columns: 1.6fr 1fr` 让网址输入占主导，市场下拉收窄。
结果区数字与刻度条左右分栏，维度分六格以 1px 间隙相连（不是六个独立卡片）。

**组件状态**：按钮/输入/选择器/分段控件/checkbox 全部写全 default/hover/
active/focus-visible/disabled。focus-visible 是 2px 琥珀描边，**不摘掉 outline**。
触摸目标 ≥ 44px。**颜色永不单独承载信息**，严重级徽标永远带文字。

**动效**：只在两处——刻度条的 `width`（600ms ease-out，进度不是装饰）与
轮询指示的旋转。其余状态变化走 120ms 颜色过渡。全部尊重
`prefers-reduced-motion`。

**图标**：不引图标库。箭头、分隔、刻度全部用 CSS 或字符画，保持同一网格。

**空/载入/错误**：三态都写了文案。载入有进度条与秒数；空态明确说
「只覆盖了这次抓到的 N 个页面」；错误给可执行的下一步，不是「出错了」。

## Phase 3 — slop 审计

| 检查项 | 结果 |
|---|---|
| 主字体非 Inter/Roboto/Arial/system | ✅ IBM Plex + 完整回退 |
| 无蓝紫渐变 | ✅ 强调色为琥珀 OKLCH(0.52 0.115 62) |
| 无发光阴影 / 玻璃拟态 | ✅ 全系统零阴影 |
| 圆角未 blob 化 | ✅ 最大 4px |
| 无渐变文字 / 无装饰性光球 | ✅ |
| 数字用 tabular-nums 且右对齐 | ✅ |
| 按钮按重要性排名而非按含义配色 | ✅ 主按钮墨黑、次按钮描边 |
| 状态矩阵完整 | ✅ |
| 焦点可见、键盘可达 | ✅ |
| 触摸目标 ≥ 24px | ✅ 表单控件 42–44px |
| 颜色非唯一信号 | ✅ 徽标带文字 |
| 尊重 prefers-reduced-motion | ✅ |
| 密度匹配工具型应用 | ✅ |
| 未用 stock 图 / 渐变球 | ✅ 零图片依赖 |
