# SEOClaw

扫一遍你的网站，告诉你**先改哪三件事**。

不是给你一张三百行的红字清单——那种清单你收藏完就再也不会打开。

## 先说它跟别的工具有什么不一样

我拿 107 个真实网站试过：博客、电商、文档站、政府站、中文社区、大型企业站。一个一个开浏览器回源核对，不是看它说得像不像，是看它说得对不对。

**结果：严格准确率 97%。** 剩下 3% 的那几条，是人工翻源码一条一条抓出来的。

97% 这个数字为什么值钱？因为 SEO 工具的失败方式很特别：**误报的代价不是"漏了"，是"你照着改了，结果更糟"。**

举两个它故意闭嘴的例子：

- 某论坛屏蔽百度收录——那是论坛自己的选择。它原本报"危险：屏蔽百度"，用户照做，论坛流量直接归零。现在它降级成一句「可能是有意为之」，然后不说了。
- 某电商站 25 页里 24 页是结账页，主站被判 0 分。但结账页带 `noindex` 是**正确配置**。现在它只算本站的页面。

**这就是我说的"只说实话"：宁可少报，不报假的。**

## 装

```bash
pip install seoclaw
```

Python 3.11 以上。就这一条，别的都不用管。

## 用

```bash
seoclaw scan example.com
```

完。报告直接打在屏幕上。想存文件就加 `-o report.md`。

看看它到底会查些什么：

```bash
seoclaw rules
```

### 几条常用的

| 你想做的事 | 加这个 |
|---|---|
| 只看中文站的问题 | `--market baidu` |
| 扫描别家客户的站（一次多个） | `--db` |
| 中断了想接着跑 | `--checkpoint ./ck` |
| 出一份能直接发客户的报告 | `--html report.html` |
| 你的站是 Vue/React 做的 | `--render-js` |

完整参数 `seoclaw scan --help` 都有。

## 它会检查什么

**默认 39 条**，覆盖最要命的那些：title、description、H1、canonical、noindex、图片 alt、内链锚文本、软 404、结构化数据……

还有三套按需加载的：

- `--market google`：语言声明、viewport、hreflang
- `--market baidu`：中文标题长度、ICP 备案、百度移动页
- `--market cnh_eco`：微信搜狗索引

另外有个 `geo` 包管 AI 搜索的可引用性，**默认不加载**——它那 4 条还没经过 107 站那种级别的验证，混进来会拖累另外 35 条已经验过的。要用就显式 `--market geo`。

## 关于礼貌

它默认每个域名每秒只发 3 个请求，会遵守 `robots.txt` 和对方声明的 `Crawl-delay`，遇到 429/403 自动降速，连续失败 5 次直接停手——人家在拉黑你了，继续打只会让封禁更久。

所以它有个硬限制得跟你说清楚：**1000 个页面的站要扫 5 分半，不是 5 分钟。**

这是限速算出来的死数（每秒 3 个 × 1000 页 = 333 秒），不是代码慢。想更快就得提高速率，但那样是在拿你自己的 IP 风险换时间，我默认不这么干。

## 存进数据库（可选）

```bash
seoclaw scan example.com --db seo.db
```

页面、问题、关键词都存下来，之后能对比这个月和上个月的变化。**不给 `--db` 就什么都不存**，不会在你机器上偷偷建文件。

## 架构（想知道细节的看这段）

```
backend/seoclaw/
├── crawler.py       抓取：限速、自适应降速、熔断、代理轮换、断点续传
├── extract.py       HTML → 页面数据
├── audit/
│   ├── engine.py    规则执行 + 覆盖率判断
│   └── rules/       base / google / baidu / cnh_eco / geo
├── keywords/        关键词扩展 + 聚类（纯离线，不需要任何 API key）
├── db/              9 张表 + 数据库迁移
├── report.py        Markdown 报告
├── report_html.py   单文件 HTML 报告
└── api/             HTTP 接口
```

一万一行代码，七千行测试，505 个测试全绿。

### 数据库

9 张表：站点、任务、页面、问题、关键词、SERP 快照、内容建议、建议动作、排名历史。

```bash
cd backend
alembic -c migrations/alembic.ini upgrade head
```

⚠️ 上线必须走迁移。用 `create_all` 只会建空表，**不会给已有的表补新列**——混着用会出现"测试里好好的，一上生产就 500"。

### HTTP 接口

```bash
uvicorn seoclaw.main:app --port 8000
```

八个端点：健康检查、站点增删查、触发扫描、查任务、查问题、取报告。

## 几条写死在代码里的原则

这些不是风格偏好，是踩过坑之后钉死的：

- **覆盖率不够的时候，站点级规则必须闭嘴。**「我没发现指向它的内链」这句话，只有在确信"大部分页面都看到了"时才成立。
- **报告里必须列出没审到的页面。** 有页面引擎整页跳过了却不说，读者会把"没审成"理解成"没问题"。
- **没有付费数据源的时候，搜索量就留空。** 填 0 等于说"这个词真的没人搜"，用户会因此放弃一个其实有量的词。
- **规则只报有正面证据的。** 「我没搜到」推不出「它没有」——所以很多规则在覆盖率不够时会主动沉默。
