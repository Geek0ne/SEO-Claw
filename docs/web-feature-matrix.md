## 盘点口径

后端本身没有的（无数据源/未实现），**不造假界面**，在文末如实列为路线图。

## 设计系统

界面按 `DESIGN.md`（唯一事实来源）重建：纸白底、墨黑字、琥珀唯一强调色、
印章红仅用于严重级徽标、零阴影、圆角 2px/4px、数字与规则编号等宽体、
健康分为**带刻度的量规**（0–100 十一道刻线 + 墨黑指针）、
颜色永不单独表意、focus-visible 保留、触摸目标 ≥44px、尊重
`prefers-reduced-motion`。零外部依赖（无 CDN / 字体 / 框架）。

## 后端能力边界（无数据源 / 未实现，**不造假界面**）

以下条目缺的是**数据源或实现**，不是接线。界面一律不做「看起来能用其实没有」的占位：

- 日级排名与 SERP 快照的**数据源**：导入通道今天三层都通了
  （`POST /sites/{id}/rankings`、`POST /sites/{id}/serp` 收结构化数据，
  `POST /sites/{id}/rankings/import`、`POST /sites/{id}/serp/import` 收原始导出，
  CLI `rank-import` / `serp-import`，界面上传卡）；但**搜索量、曝光、竞品正文**
  这类需要第三方数据的字段仍然没有来源，没来源就不填 0。
- 竞品追踪与内容缺口分析（位次已能落库并喂给 Brief；竞品**正文**仍无数据源，
  代抓属付费第三方，见 `PLAN.md` P2 #15）
- 内容日历、逐页改写稿（`suggestions` 表已建，服务层未接）
- PDF / Excel / PR-diff 导出

## 界面接线的不变量用例

`test_web.py::test_every_api_path_the_page_uses_is_a_real_route`：把页面上 JS 写到的
每条 `/api/v1/...` 路径（模板段折成通配）拿去和 OpenAPI 里真实注册的路径逐条核对，
对不上就红。它替代了「查中文字面量证明功能存在」这种自我安慰——文案在、壳子就在，
点下去 404 一样是废的。取数走 `app.openapi()["paths"]` 而不是 `app.routes`：
API 路由挂在子应用上，裸 `app.routes` 一条 API 路径都看不到，会把 30 条全判成不存在。

补齐优先级与方案见 `PLAN.md`。
